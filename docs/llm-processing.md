# 通知内容处理与 LLM 配置

在控制台的「配置与邮箱设置」页，第一张卡片是「通知内容处理」。

1. 填写接口基础地址，例如服务提供的 `https://服务域名/v1`，以及模型名称。兼容 OpenAI Chat Completions 接口（JSON 模式）；本地服务允许 `http://127.0.0.1:端口/v1`。
2. 填写 API Key 和请求超时（1–60 秒）。本地免鉴权接口可不填密钥。使用百炼 DeepSeek 等混合思考模型时，可勾选「关闭 thinking（百炼 / DeepSeek）」；保存配置和测试提取均使用此选项。
3. 点击「保存配置」。密钥输入框留空保留已有值；勾选「清除本机保存的密钥」可删除已保存密钥。
4. 点击「LLM 提取」保存当前表单并启用；点击「本地规则」立即切回本机识别。
5. 展开「测试 LLM 内容提取」，输入一条测试通知，点击「测试提取」。测试可使用未保存的表单，不修改数据库或邮件队列，不发邮件。

LLM 模式会将新消息正文、附件名称、消息发送时间和消息类型发送到配置的接口，不发送邮箱凭据、群名或发件人。接口可能产生调用费用；测试仅发送输入区内容。

提取结果包括标题、摘要、活动时间、报名开始时间及报名链接。缺失的信息保留未注明；发送时间缺失时不猜测年份和相对日期。文件仅保留文件名，不读取或推测正文，未展开转发卡片不推测子消息内容。

校区筛选统一用于本地规则、LLM 成功结果和失败回退：仅提醒石牌校区／石牌校园（含地点简称“石牌”）；大学城校区／校园、佛山校区／校园、南海校区／校园及其他明确校区不提醒。未提及校区仍可通知，不根据教学楼名猜测校区。优先依据讲座地点、报告地点、活动地点、举办校区等字段；主讲履历、主办单位、报名对象中的校区不作为举办地点。多会场明确包含石牌可参加场地时可提醒；地点明确改动时按改动后的地点判断。校区筛选由本机统一执行，模型的肯定结果不能绕过；被筛除的原文仍保留在采集消息中，但不生成讲座记录和邮件任务。

通过校区筛选后，识别到讲座相关内容即产生通知，不按置信度、时间完整度、取消或是否入选过滤。模型判为无关但本地规则识别出讲座线索时仍保留通知。接口超时、鉴权失败或返回格式错误时，回退本地规则；相关记录显示「LLM 失败 · 规则回退」。规则没有识别到线索的原始消息仍可在「采集消息」查看。

切换对下一条新消息生效，原有记录不会自动重算或补发。新版本监控进程读取每条新消息前重新加载处理设置，无需因切换方式重启。升级前已启动的旧版监控需要重启一次以加载新增代码。邮件格式随处理方式自动切换：本地规则发送原文；LLM 成功时发送主题、摘要、活动时间、报名开始时间及报名链接，并在下方保留完整原文。LLM 失败回退时使用原文格式并提示回退，文件消息仍仅标注文件名。每条通知按生成时的处理方式保存邮件格式，切换不会重算或重发已有通知；已入队通知也不会因之后的切换而改版。网页邮件预览与实际投递共用同一模板。

密钥独立保存为配置路径后加 `.llm-key` 的本机文件，例如 `config.toml.llm-key`，权限为 `600`；不保存在 TOML，不通过 API 回传。也可在监控进程环境中设置 `WECHAT_LLM_API_KEY`，或表单中指定的环境变量；本机保存文件优先。清除本机密钥不会删除环境变量中的密钥。

默认配置为 `processing_mode = "rules"`，不访问 LLM。示例 TOML 已列出 `llm_base_url`、`llm_model`、`llm_api_key_env`、`llm_timeout_seconds`。

接口格式参考：[OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。服务需支持 `response_format: {"type":"json_object"}`，不支持的接口会显示测试错误，监控处理回退本地规则。

「关闭 thinking」配置键为 `llm_disable_thinking`，默认为 `false`。勾选时向 HTTP 请求体顶层添加 `enable_thinking: false`；不勾选省略该参数、遵循服务默认设置。参考[百炼 DeepSeek API 文档](https://help.aliyun.com/zh/model-studio/deepseek-api)。

## 多服务与配置保存

API Key 保存后仅清空输入框以防回显，已保存密钥会持续使用，留空保存不会删除。设置持续用于后续所有新消息，绝非一次性。

正式群和“邮件测试”可以是两个独立进程、两份消息库。数据库下拉框或服务行的“查看消息”用于查看相应服务的消息，保持群历史隔离，不切换监控群。配置页服务列表显示每个进程实际使用的处理方式、是否跟随控制台处理设置、最近处理结果和错误。

需要共享处理配置的服务可在其 TOML 根级设置 `processing_config_path = "/主配置的绝对路径/config.toml"`。仅引用处理参数和密钥来源，群名、采集设置、邮件发送开关和数据库保持独立。跟随配置的控制台显示来源路径且只读；请在来源配置的控制台保存，避免写入被共享来源覆盖的无效本地设置。测试也使用来源配置及其密钥，但保留本服务群上下文、不入库不发信。主配置修改后，所有已绑定服务对后续新消息热加载。首次从旧进程升级需要重载服务；未绑定服务仍使用自身设置，页面明确标示。

## 邮件投递提示

讲座列表与邮件队列会显示识别后的投递状态：等待调度、等待邮箱配置、服务未启动、仅预览、发送中、发送失败等待重试（含下次重试时间与最近错误）、停止重试、已提交 SMTP。识别成功不等于邮件已发送；SMTP 接受也不保证已经到达收件箱。

独立测试进程若需要重用现有安全存储的邮箱配置，可在其根级指定 `email_credentials_config_path` 指向主配置。SMTP 凭据共享与 LLM 参数共享是两个独立选项；凭据仍从原 Keychain / DPAPI 安全存储加载，不写入 TOML。
