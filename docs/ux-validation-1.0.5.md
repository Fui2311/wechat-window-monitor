# 1.0.5 状态恢复与日历导出验收

本轮使用合成群、临时配置和独立数据库，所有原生控制均为测试替身。未修改生产配置或常驻监控，未发送 SMTP 或微信。

## 复现与结果

| 问题 | 修复前实际证据 | 修复后实际结果 |
| --- | --- | --- |
| 服务表卡住读取失败 | 已安装 1.0.4 控制台先返回空服务表，再模拟 503；恢复后连续返回 200，页面仍显示错误 | 下一次自动读取恢复为空服务表，无需手动重载或数据变化 |
| 空讲座列表卡住错误 | 合成历史库有采样基线、无讲座；503 后恢复 200，KPI 已成功而列表仍报错 | 同样场景自动恢复为空结果，错误去重状态也重置 |
| 历史空库文案误导 | 文案声称将继续采集该历史群的新讲座，实际管理群仍是 A | 历史库明确只读，指向采集消息或返回当前群；搜索、Demo、当前群分别提供对应提示 |
| 服务状态不一致 | 列表将 running=true 的启动进程直接显示为监控中 | 合成 starting 状态在页头和表格均为服务启动中；回归覆盖等待窗口、数据库异常、无响应和未知采集状态 |
| 日历错误无反馈 | 接口返回 503，旧页面仍显示绿色正在导出且没有失败原因 | 显示模拟错误原因并恢复按钮；接口恢复后浏览器实际保存有效 ICS，文件含 A 组讲座和报名链接 |
| 空日历 | 所选历史库没有明确活动时间 | 页面说明没有可导出项目，本次不下载文件 |

浏览器实际下载文件已读取验证 BEGIN/END:VCALENDAR、合成 A 组标题与链接，随后移至本机忽略目录 `state/ux-audit/calendar-browser-recovery.ics` 作为证据。页面仅声称已请求浏览器下载，不将请求等同于收件、导入或任何真实通知。

## 自动回归和范围

29 项 Node 回归通过。新增服务表和空讲座恢复回归在原代码上先失败；修复后通过。其他新增覆盖空提示上下文、页头/表格共同状态投影、服务可见字段变更、导出 HTTP 错误、有效文件、空/无效响应、切库及 A→B→A、关闭后的迟到响应。测试 DOM 保留真实渲染输出，因此恢复回归不以渲染桩替代被测路径。

JavaScript 语法、ruff 与差异空白检查通过。Python 业务未改，跨平台 310 项测试、原生编译和安装打包以对应提交 CI 为准。实际浏览器只使用合成数据，不代表微信采集、SMTP 送达或日历应用导入验收。

本机复现日志及截图位于忽略目录 `state/ux-audit/recovery-before.log`、`recovery-after.log`、`recovery-red.log`、`empty-calendar-1.0.5.png`；不会打入发布包。

构建后补充验收：wheel 在仓库外新环境通过 CLI/API 冒烟，sdist 可重新构建，Mac ZIP 的 CRC、80 个清单文件 SHA256、闭合文件范围和文档链接检查通过。另将 wheel 装入专用 UI 虚拟环境，导入位置确认为 site-packages；实际页面在合成数据库异常下的页头与表格均显示数据库异常，导出 503 会显示原因，确认发布包含有修复。
