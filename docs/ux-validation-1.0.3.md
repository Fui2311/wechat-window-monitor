# 1.0.3 控制台刷新与操作范围验收

本轮使用临时配置、合成群 A/B/C、独立 SQLite 和本机 HTTP 控制台。服务启停、群窗口探针与邮箱授权均为测试替身；真实启动被禁止。手工浏览器夹具未读取生产数据库，未发送 SMTP 或微信，也未更新已安装的常驻监控。

验收范围勘误（1.1.1）：旧自动测试未完全替换全局发现根与用户目录，可能枚举本机历史/服务元数据，因此不能把整套自动测试一概称为完全隔离。本轮浏览器夹具的隔离证据不受影响；后续改进与范围见 [1.1.1 报告](validation-1.1.1.md)。

## 已复现与修复

| 问题 | 修复前证据 | 修复后实际观察 |
| --- | --- | --- |
| 手动刷新漏掉新增数据源 | 页面打开后创建 C 库，点击刷新仍只有 A/B，整页重载才出现 C | 同一页面点击刷新即出现 C，未保存的模型草稿仍保留 |
| 过期停止确认作用于新群 | 当前群为 B，带旧群 A 的停止请求仍返回 200 并调用 B 的假停止器 | 后台返回 400，拒绝操作；前端重新同步管理群、活动库和记录 |
| 多页面选库记忆干扰活动库同步 | 第二页已把共享记忆写成 B，第一页因此漏判 A→B 的变化 | 各页按自己上次观察的活动库判断；旧确认拒绝后数据源、范围和未编辑的目标群输入同步 |

双页面浏览器验收进行了 A→B、B→A 两次切群。测试日志只记录两次切群所需的假停止调用，旧停止确认均未增加调用。普通重启不额外传入 `send=false`，继续沿用服务已有模式；真实发信仍需明确确认。

## 自动验证

- 310 项 Python 测试通过；macOS 跳过 2 项 Windows DPAPI 专属测试。新增 HTTP 回归覆盖开始预览、开始发信、重启、停止四种过期群请求，验证拒绝前不调用原生控制或自启动变更。
- 19 项 Node 前端状态回归通过，覆盖刷新顺序、新库发现、重复点击合并、历史选择和草稿保留、离线重试、多页面活动库变化和目标群草稿。
- JavaScript 语法检查、ruff 与差异空白检查通过。
- wheel 在仓库外新虚拟环境安装，通过 CLI、10 个 HTTP 页面/API、重复导入、预览队列和日历冒烟；源码分发包可重建。
- Mac ZIP 的 CRC、80 个清单文件的 SHA256、允许文件范围及本地文档链接通过检查。

原生助手编译、多平台验证与发布产物一致性以对应 GitHub CI 和正式 Release 为准。上述测试不代表微信桌面实际采集或邮箱最终送达验收。

Antigravity 旧有两次有界任务均显示执行错误、没有可整合报告。本轮重试入口时新提示未进入输入框、发送按钮仍禁用，因此未有效派发。代码、文档、集成和实际验收由 Codex 完成。

安装包交互复核：独立虚拟环境从 1.0.3 wheel 安装，服务器导入路径确认位于该环境的 `site-packages`。页面打开后新建 C 库，手动刷新发现 C，模型框中的「安装包验收保留草稿」不变；选择 C 后范围提示明确查看 C、操作 A。截图与服务器导入证据保存在本机 `state/ux-audit/wheel-refresh-1.0.3.png` 和 `wheel-ui-1.0.3.log`，不进入分发包。
