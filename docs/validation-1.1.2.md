# 1.1.2 分页与首次体验验收

## 可复现缺陷

向合成库写入五条消息，每页两条，读取第一页后追加新消息。旧实现第二页从第三条偏移读取，连读得到 4、3、3、2，第三条重复，后续边界也会移动。回归先红后绿，日志 pagination-red.log / pagination-green.log 保存在本机忽略目录 state/ux-audit。

查询现在在只读事务中取得最大 rowid，后续页使用 rowid 上界。统计、搜索、分页沿用同一追加边界，不改 SQLite 格式、不写库；包括较早时间的补采也会被边界排除。它不冻结讲座关联重新分析或外部删改；用户主动刷新、返回第一页、改变分类/搜索会读取新的边界。

搜索旧请求可能在输入已改变、200ms 防抖尚未发出新请求时写回旧结果。输入现在立即使旧请求失效，标明保留的上次内容并禁用翻页；新增确定性回归控制旧响应与新计时器，证明迟到响应不会覆盖等待状态或新结果。

- 320 项 Python 回归通过（本机 macOS 跳过2项 Windows DPAPI），35 项前端回归通过；ruff、JS 语法、版本标签与差异空白检查通过。全部发现查询限定临时根和假用户目录。
- 源码浏览器合成206条消息，第二页显示101–200，首条历史105。后台追加一条并经过自动刷新，第二页仍显示101–200 / 206，首条不变；手动刷新回到1–100 / 207，顶部出现合成新增消息。搜索历史105使用同一实际页面核查。
