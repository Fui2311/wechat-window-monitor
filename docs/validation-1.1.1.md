# 1.1.1 数据源发现与自动测试隔离验收

## 发现缺陷和修复

旧版数据源查询只在文件名检查 before/previous/last-good，祖先目录未统一处理。用有效 SQLite 采样表重现后，1.1.0 浏览器将 `before-engineering/nested/tracker.sqlite3` 列为普通历史库；项目上层路径含 backup 时又会误排正常历史和明确服务根。旧备份回归只创建空文件，不能证明有效备份被排除。

查询和服务发现现在共用相对路径过滤；自动数据库遍历在进入快照/隐藏子树前剪枝，重复搜索根去重。当前活动库和明确识别的服务根仍可使用，即使其上层路径带备份字样。过滤仅改变自动发现，不删除文件。

5 条新增回归覆盖有效备份/隐藏目录、备份命名的上层路径及明确服务、快照数据库不被打开、遍历确实不进入快照子树，以及测试发现根正确恢复。前三条产品回归在原代码上失败，修复后通过；路径比较按实际解析结果处理 macOS /var 与 /private/var 别名。

## 测试隔离范围勘误

源码检查发现，旧控制台自动测试与安装冒烟沿用全局 PROJECT_ROOT 和真实 Path.home，可能枚举工作区数据库及本机 LaunchAgent 元数据。此前对自动测试隔离范围的表述过宽，不能将旧全量测试一概称为完全不读取本机历史元数据。旧查询使用只读连接，测试中的控制操作指向临时配置或替身；没有执行生产监控升级、生产启停或真实发信。

本轮增加统一测试夹具：queries/discovery/handler 的发现根与用户目录指向临时树，服务状态从夹具 JSON 读取，拒绝越界状态查询，避免触及真实进程或控制通道。HTTP 测试、模型控制台测试及测试数据重置的发现路径使用该夹具；纯队列测试原本已直接使用临时数据库。修正了旧多服务测试中未覆盖实际 discovery.read_status 调用的模拟目标。

安装冒烟也限定相同三处根、假用户目录与假服务状态，并在请求前断言隔离生效。报告明确输出 discovery_isolated=true。手工浏览器夹具另有独立根和原生替身，其合成数据验收仍有效。

## 验证结果

- 隔离后的全量 319 项 Python 回归通过，macOS 跳过2项 Windows DPAPI 专属测试；33项前端回归、ruff、差异空白与版本一致性检查通过。
- 实际修改 pyproject 后，只读版本检查先发现漂移，--write 同步7个派生文件，后续检查通过；历史变更记录在同步步骤保持不变，新增版本条目单独编辑。
- wheel 仓库外安装后通过14个页面/API、重复样例、预览、日历及发现接口；sdist可重建。MacZIP83个清单文件的SHA256、CRC、允许文件范围和本地文档链接通过。
- 源码浏览器中正常历史库保留、有效备份不再出现，备份与历史文件字节未变；最终1.1.1 wheel独立安装后重建相同夹具，实际页面再次确认正常历史可查看、备份不在下拉框中，导入位置为该环境site-packages。

本轮没有升级或操作生产常驻监控，没有发送真实SMTP或微信。以上不代表真实桌面采集或邮箱送达验收。证据保存在本机忽略目录 state/ux-audit，包括 discovery-red.log、discovery-green.log、tests-isolated-discovery.log、smoke-1.1.1.log 和 wheel-discovery-1.1.1.png。
