# 可选自动转发检查（Windows 0.3.0 历史记录）

macOS 当前操作入口见 [快速启动第4节](快速启动.md)：源码中的 `activate_click` 已在“邮件测试”群实测，无需用户手动打开卡片，会在空闲时短暂切到微信，读完恢复原应用与鼠标。该模式尚未部署到本机正式服务。详细证据见 [Mac 自动读取实验](macos-forward-background.md)。

以下保留 Windows 0.3.0 的运行方式、UIA 约束和历史验收，不作为 Mac 新模式的启动说明。

本轮已将自动转发驱动接入监听。普通采集仍只读；显式 `--expand-forward` 或配置 `auto_expand_forward = true` 才允许打开卡片。邮件发送仍独立由 `--send` 控制。

## 运行

```powershell
python -m wechat_tracker watch --interval 15 --include-existing --expand-forward
```

启动后切回目标群的独立窗口，将需要检查的卡片完整显示在消息列表内，等待至少3秒不操作鼠标键盘。程序不主动抢焦点；从终端执行 `--once` 时，前台仍是终端会使展开被拒绝，因此首次推荐持续轮询。可见消息分析和既有提醒调度不受单张卡片展开失败影响。

不加 `--include-existing` 时，初次可见消息只是基线，之后不会因为自动展开而把基线当新公告。显式加入该选项可检查已保存的基线。默认命令只生成到期邮件预览。

## 来源和操作约束

1. 重新核对唯一独立群窗口、内部精确群名、消息页和消息列表。
2. 重新匹配当前父卡片runtime id与正文SHA-256；卡片须完整可见，点击点不能被其他窗口遮挡。
3. 要求目标群处于前台、用户已空闲，且同进程没有预先打开的合并转发详情。只单击一次核对过的卡片。
4. 等待唯一新开的精确标题详情窗口，核对PID和唯一消息列表，只读取已验证的子项。遇到输入、窗口或群名变化停止剩余操作。
5. 只使用详情自身的UIA `ScrollPattern`进行有界滚动；没有该接口则保留当前可读子项并标记不完整。不向主群发送滚轮或按键。
6. 关闭本次新开的详情，并验证回到同一群窗口后，才接受 `verified_parent_open` 来源绑定。用户已接管时保留窗口供检查。

手工 `forward` 命令依旧采用显式本地父ID，保持 `source_group_verified=false`；泛标题不会自动获得可信群来源。文件、图片和嵌套转发只保留待补全标记，自动驱动不下载或打开它们。

## 默认限额和恢复

| 配置项 | 默认值 | 含义 |
| --- | --- | --- |
| `forward_max_cards` | 3 | 每轮最多尝试的父卡片数 |
| `forward_max_pages` | 5 | 每张详情最多读取的页数 |
| `forward_idle_seconds` | 3 | 打开卡片前的用户输入空闲秒数 |
| `forward_timeout_seconds` | 25 | 单次原生进程的硬超时秒数 |
| `forward_partial_retry_seconds` | 600 | 部分读取后的补读间隔 |

完整结果保存在SQLite的 `forward_reads`，重启后直接使用缓存。部分结果也会缓存，超时后才尝试补读；补读失败不会丢失已经取得的正文。失败从30秒指数退避，最长15分钟。一次交互错误会停止本轮其余卡片的展开，后续轮询再尝试。

硬超时会终止驱动，可能来不及关闭已打开的详情。下次轮询会因已有详情而拒绝新操作；检查并关闭该详情后可重试。UIA只覆盖当前加载数据，有限页数和内容指纹也不能证明全历史无遗漏。

## 验证证据

- 当前微信4.1.15.13：通过computer-use从目标群单击父卡片，新出现同进程“群聊的聊天记录”，读取到盖章材料和未来讲座通知，再关闭详情并确认回到原群。
- 自动驱动协议使用模拟原生结果测试来源绑定、用户冲突、部分读取、超时参数和返回验证；业务测试串联真实分析器、SQLite和邮件预览。
- `watch --once` 的JSONL入口已验证嵌套讲座/待核实线索、重复轮询去重和默认不发邮件。
- 0.3.0新增真实原生验收：在本机微信4.1.15.13由驱动重新绑定父卡片，自动单击、新详情读取、关闭并返回，耗时0.83秒，`new_window_observed/restored=true`。另由常驻服务自行完成同一卡片读取并缓存，详情句柄与手动验收不同。此次各读取1条可访问正文，历史完整性仍为false，不能推断全部卡片或历史均能完整读取。
- 证据位于Git忽略目录 `state/native-forward-e2e.json` 与 `state/service-native-forward-e2e.json`；前者为独立原生驱动，后者为实际常驻服务。SMTP尚未配置，没有发送邮件。
