# 通用微信窗口监控改造

目标：精确名称绑定任意可读微信会话窗口；独立多窗口注册/状态/数据；两种生成一次、持久版本化的识别 core；Dashboard 窗口下拉与新增卡片、完整配置、工具提示；新 GitHub private 仓库。

依赖方向：dashboard -> HTTP application -> registry/runtime -> recognition ports + SQLite repository + exact-window capture adapter。识别核心不调用讲座分析器/场地策略/旧通知业务；复用底层只读原生采集及资源。

规则流程：目标 -> 显式调用 LLM -> 草稿 schema 校验 -> 用户试测/确认启用 -> 持久规则版本 -> 新消息识别。语义 core 使用保存的语义规则；本地 core 执行有限 DSL，绝不执行生成 Python/JS/shell。目标/模式变更不隐式复用旧规则。失败记录并可重试，不将模型异常伪装成不命中。

运行：统一 dashboard 进程管理多个独立轮询任务，状态区分停止/启动/监控/等待窗口/识别失败；绿点仅成功采样且正在监控，灰点停止，异常保留文案。停止/关闭等待当前任务退出；重启默认停止，不隐式恢复真实操作。原安装服务与数据完全隔离。

验证：合成 JSONL/假原生、临时根、假 LLM；生成次数/本地零网络/语义规则复用、隔离/去重/重启持久化、失败恢复/分页/并发、HTTP 安全、真实浏览器与独立安装。桌面真实窗口另行验收，不将假原生当真实桌面。交付新私有仓库、README、安装说明和可重现测试。
